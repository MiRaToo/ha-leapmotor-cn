# T03 车况尝试性兼容

本次适配依据国内 App 中的 T03 具名信号分支与车辆区域路由，以及 Issue #7 的反馈。尚未完成中国版 T03 的车主实测，不能据此宣称所有年款均已适配。

## 工作方式

- 其它车型继续使用现有车况请求和解析逻辑。
- T03 先使用现有请求，并保留原来的签名错误续期与一次重试。
- T03 支持数字键信号、具名 `signalMap`、具名 `data`；布尔值与数字字符串会归一化，缺失读数保持未知。
- 只有原请求一直没有有效车况时，才读取官方 `getCarRoute` 的 `appRegion`，尝试国内 App 使用的区域车况请求。没有加入未经确认的海外旧端点，也不切换国内登录链路。
- 兼容探测成功后按车辆缓存读取方式一小时；失败也有一小时冷却。原链路已正常读取过的车辆不因临时空帧切换路径。
- 限流、权限和登录失效不会触发额外探测；兼容响应出现限流时立即停止后续云端读取。兼容失败保留上一帧，不生成零电量、零里程等默认读数。

这次仅调整车况读取，不更改 T03 的控车指令或根据车型自动发送任何车控。

## 车主如何验证

1. 更新集成并重启 Home Assistant，确认官方 App 中本车有车况。
2. 对照电量、剩余续航、总里程、门锁和四轮胎压，并留意状态更新时间；车辆休眠时可能只有云端保存的旧数据。
3. 从“设置 → 设备与服务 → 零跑汽车 → 下载诊断”获取报告，注明年款、配置、主账号或共享子账号，以及哪些读数恢复。

报告中的 `diagnostics.car_state_request` 会记录使用的策略、官方服务主机、请求格式、业务码、响应类型和识别信号数。它不包含 VIN、token、签名或完整响应体；具名经纬度和归一化后的位置信号均经过脱敏。

失败后无需反复重新登录或连续刷新。诊断中持续出现签名错误、零识别信号、区域路由不可用等情况时，可据此安排下一次有针对性的只读取样。
